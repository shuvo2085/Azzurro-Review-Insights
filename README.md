# Azzurro Review Insights

A Next.js dashboard for hotel review analytics, with CSV import, Supabase persistence, Recharts visualisations and Gemini-powered operational insights.

**Live:** https://azzurro-review-insights-4tjo.vercel.app/dashboard

## Important data note

The included review records are fictional demonstration data. They are not Booking.com reviews and must not be represented as actual Azzurro guest feedback. Use only review exports or feeds that the employer provides or authorises. The monthly trend chart is also explicitly illustrative until historical month-level data is available.

## Features

- Portfolio overview: average rating, sentiment mix, property comparison and common topics
- Filtering by property and sentiment, plus free-text search
- CSV import (validated, max 1,000 rows per import)
- Ratings are stored on a **0–10** scale. If an import never exceeds 5 it is treated as a 5-star
  source and doubled automatically; override with `rating_scale: "5" | "10"` in the request body.
  Send `dryRun: true` to preview the normalised rows without writing to the database.
- Persistence via Supabase; falls back to demonstration data when unconfigured
- AI operations insights generated by Gemini from the currently filtered reviews

## Requirements

- Node.js 20.9+
- npm
- Supabase project (optional — the app runs in demo mode without one)
- Google AI Studio API key (optional until you use AI analysis)

## Local setup

```bash
npm install
cp .env.example .env.local   # then fill in the values
npm run dev                  # http://localhost:3000
```

Production build:

```bash
npm run build
npm run start
```

Quality checks:

```bash
npx tsc --noEmit
npm run lint
```

## Environment variables

See [.env.example](.env.example) for the full list.

| Variable | Purpose |
| --- | --- |
| `GEMINI_API_KEY` | Server-side Gemini key for `/api/analyze` |
| `GEMINI_MODEL` | Optional model override (default `gemini-3.6-flash`) |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase public key |
| `SUPABASE_SERVICE_ROLE_KEY` | Server-only key used by the API routes |

Never expose `SUPABASE_SERVICE_ROLE_KEY` in client code — do not prefix it with `NEXT_PUBLIC_`.

## Database

Run [supabase/schema.sql](supabase/schema.sql) in the Supabase SQL editor to create the `reviews` table and indexes. The API routes read and write through the service-role key on the server, so the service key must be present along with RLS enabled.

## Deployment

The repository is connected to Vercel; pushes to `main` deploy to production automatically.

1. Add the environment variables above to the Vercel project (Production and Preview).
2. Push to `main`.
3. Verify `/dashboard` loads and `/api/reviews` returns `mode: "supabase"` when a database is configured.

### A note on Gemini models

Google retires Gemini model ids over time — `gemini-2.5-flash`, for example, now returns `404 NOT_FOUND`. `/api/analyze` therefore tries `GEMINI_MODEL` first and falls back through other available flash models, returning a readable error instead of a raw API payload if all of them fail.
